# キーチェーン対応 実装計画（issue #25）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `.env` / `secrets.env` に `keychain://<service>` と書いた名前を、全体設定で指定した専用キーチェーンから `/usr/bin/security` で読み、1Password と同じ流れ（列挙・承認・`-e NAME`）でコンテナに渡す。

**Architecture:**
- `internal/opwrap` を `internal/secret` に改名し、参照をスキーム（`op` / `keychain`）で分ける。優先順位（全体が勝つ）の決定、キーチェーンのパスの確かめ、`security` の argv と出力の解釈もここに置く（純粋関数。`security` は実行しない）。
- `security` の実行は `app.Deps.Security`。本物は最小の環境・`Setsid`・タイムアウト付きで実行し、テストでは偽物にする。
- 値は `docker.RunSpec.SecretEnv` に入れ、`docker run` のコマンドの環境にだけ足す（引数は `-e NAME` のまま）。

**Tech Stack:** Go 1.27.4、標準ライブラリのみ、`CGO_ENABLED=0`、macOS の `/usr/bin/security`、docker CLI。

**Spec:** `docs/superpowers/specs/2026-11-19-dev-cli-design.md`（以下「設計書」）の 19 章、あわせて 6・7・8 章と 2026-11-24 の決定事項。

## Global Constraints

- 外部モジュール禁止、cgo 禁止。`make check`（test + vet + gofmt）が通ること。
- ユーザー向けのメッセージ・エラーは日本語で `sigil: ` から始め、標準エラーへ。失敗は終了コード 1。エラーは `lore` / `loref`（1 行目が用語、2 行目が普通の言葉）。
- コメントは日本語で「なぜ」を書く。特にセキュリティ上の理由。
- 値・キーチェーンのパスワードを、コマンドライン引数・ログ・エラーに出さない。`security` の標準出力はエラーにも `%v` にも含めない。
- `security` は `/usr/bin/security` の絶対パスで実行する。`LookPath` を使わない。シェルを通さない。
- service 名: `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`。
- 専用キーチェーン: リンクを解いたパスが `<リンクを解いたホーム>/Library/Keychains/` の直下、`login.keychain-db` / `login.keychain` ではない、通常のファイル、持ち主が実行ユーザー。`security` にはリンクを解いたパスを渡す。
- `security` の子プロセス: 環境は最小（sigil の環境を引き継がない）、作業フォルダ `/`、標準入力 `/dev/null`、`Setsid: true`、タイムアウト 120 秒。標準出力の上限 64KiB（超えたらエラー）。
- 新しい環境変数は読まない（`config.deniedEnvs` に足すものはない）。
- テストで本物の `security` や `op` を実行しない。利用者のキーチェーン・`.env` の値を読まない。
- コミットは**ユーザーに確認してから**（CLAUDE.md）。各タスクの「コミット」は提案のタイミング。コミット後の security-guidance のフックの指摘は、対応するか理由を書き残す。
- 実機の確認では `sigil:dev-test` と一時フォルダ、テスト用キーチェーン `~/Library/Keychains/sigil-dev-test-*` だけを使う。sigil を実行するときは `PATH=/usr/local/bin:/usr/bin:/bin` を付ける。

## Review Focus

1. **ホームがリンク経由のパス**（`/Users/x` が別の場所を指す、`UserHomeDir` と EvalSymlinks の結果が違う）→ ホームもリンクを解いてから比べ、正しい専用キーチェーンを拒否しない（Task 4 にテスト）。
2. **`~/Library/Keychains/` の下のサブフォルダ**（`~/Library/Keychains/<UUID>/...` など）→ 直下ではないので拒否する（Task 4 にテスト）。
3. **値の末尾が `\n\n` や `\r\n`** → 取り除くのは最後の `\n` 1 つだけ（`\r` は値に残る）。値を勝手に変えない（Task 4 にテスト）。
4. **`.env` の `export NAME=keychain://x` や `NAME="keychain://x"`** → `op://` と同じように読める（Task 2 にテスト）。
5. **op の組だけのプロジェクトの既存の承認記録** → 改修後もハッシュが同じで、聞き直されない（Task 6 にテスト）。
